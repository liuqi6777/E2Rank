## 1. [P1] 基准参与配方选择，当前披露不足以界定泛化结论

位置：`main.tex:151`、`sections/appendix.tex:468`、`sections/experiments.tex:197`。

复现声明明确说 BRIGHT 和 QA suite 参与 configuration choices；附录明确没有内部 BRIGHT development split。历史实验记录也包含根据 BRIGHT 反馈调整 alignment、候选和 reward 的过程。但 BRIGHT 的正文 evaluation 段没有说明选择范围，复现声明的 “as noted in Section 4” 对 BRIGHT 并没有对应解释。

固定最终 checkpoint、三 seed 和清除训练集重叠都不能消除 benchmark-level 配方选择偏差。QA 的五个数据集可以称为“不提供训练 query 的 out-of-domain 数据”，但如果它们参与选择，就不能同时当作未接触的模型选择 holdout。

建议：在正文说明哪些参数由哪些数据选择、基线获得什么调参预算；如有真正未用于选择的数据或模型转移结果，把它作为独立验证。否则保留当前结果，但将其准确定位为 benchmark-informed adaptation。不能事后把已参与选择的数据重新命名成独立 test。

## 2. [P1] 监督信号不匹配，使“RL 优于监督目标”的归因不够充分

位置：`sections/experiments.tex:64`、`sections/appendix.tex:342`、`sections/appendix.tex:499`、Table 2。

InfoNCE 使用原始 binary positives；LambdaLoss 使用 teacher grades；完整 RELER 同时使用 teacher-graded nDCG 和由原始 binary annotations 定义的 pairwise reward。因此两个监督基线分别缺少 RELER 使用的一种监督信号。“RELER 与 LambdaLoss 使用相同 teacher grades”是对的，但不等于完整监督输入匹配。

这在 Q3E-0.6B 原始 query 上尤其重要：完整 RELER 为 23.38，InfoNCE 为 22.64；去掉 binary pairwise 后为 22.72。完整配方对 InfoNCE 的 +0.74 中，+0.66 与加入另一种监督信号同时发生。这不能直接证明增益只是标签造成，也不能排除这一解释。

建议：若补一个核心实验，优先考虑同候选、同监督的 differentiable control，例如 teacher-graded LambdaLoss + binary pairwise logistic/InfoNCE，并交代各自调参预算。现有 graded-only CMP 与 LambdaLoss 的结果仍可支持一条较窄的同标签比较。当前主表应解释为完整训练配方比较。

## 3. [P1] RAG reward 与 baseline 的实际定义没有写完整

位置：`sections/experiments.tex:187`、`sections/additional_results.tex:108`；核对来源：`src/rag/relevance.py`、`configs/experiments/iclr2027/suite_g3_r2.yaml:203`、`:299`、`build_rag_results.py:16`。

正文与附录介绍了 binary passage qrels，然后直接称训练使用 graded nDCG，却没有给出 RAG 的分级规则。实现实际使用 qrel=3、evidence=2、answer-containing=1、其他=0，按该优先级覆盖。它不是附录中 ReasonRank 的 teacher-rank 3/2/1/0 映射。

表 3 的 InfoNCE 实际来自 `CL-AnswerMasked-Anchor050`：含答案但不是 qrel positive 的文档从负例分母中移除。该规则也没有在稿件中说明。因而 RAG 对比除了已披露的 offline candidates versus dynamic full-index access，还改变了标签使用方式。

建议：增加一张紧凑的 RAG 配置表，列出三种标签来源、graded gains、InfoNCE masking、训练样本数/拆分、optimizer/LR/batch、G、alignment、候选数量、index search 配置和 generator prompt/解码/长度设置。配置文件中这些信息大多已经存在，补文稿不需要重新训练。若要归因于 RL，还需匹配候选获取与监督的 baseline。

## 4. [P2] 摘要的无条件胜出和组件有效性表述超过现有证据

位置：`main.tex:120`。

“consistently outperforms InfoNCE”没有限定 original queries，而 Q3E-0.6B GPT reasoning 的均值是 37.23 versus 37.38。4B 两种 query 的差值仅 +0.38、+0.09，且配对 seed 差值各有一次为负，不能表达成普遍稳定优势。

“ablations ... confirm that each contributes”也过强：paired/query-only/document-only 对照的 reward path 与 product 不同，附录明确说尚未验证等价性。它们不能单独确认每一个组件的因果贡献。

建议摘要改成明确的事实：original-query BRIGHT 上三个 backbone 均提高平均值；六种 model/query 条件中五种提高。将机制结论集中在已匹配的 CMP 消融和 pairwise reward 消融上。

## 5. [P2] CMP 最重要的定量证据没有进入当前 PDF

位置：`sections/experiments.tex:94`、Figure 2(a)、`sections/appendix.tex:593`。

正文声称完整梯度方差下降数百倍，但 Figure 2(a) 只显示一个初始状态、一个 microbatch 的二维投影；附录 D.7 只解释 measurement protocol，没有九组完整梯度方差/SNR 数值表。现有材料无法让只读 PDF 的审稿人检查这个核心量化结论。

原始 `paper/analysis_results/gradient_probe_k0_pairwise/probes.csv` 确实包含九组数据，复算的下降倍数为约 291–590。它们来自三个状态（初始化、step 50、step 113）× 三个 microbatch，因此正文 “nine ... at the same checkpoint” 也应改为三个 checkpoint states。

建议直接恢复完整 probe 表或图，报告 V_CMP/V_RLOO、SNR、draw 数与配对条件；明确全梯度方差是实证结果，理论仅保证逐项方差。二维投影的八轴中选轴规则也应说明。此项无需新实验。

## 6. [P2] “训练耗时与 contrastive learning 相当”缺少测量支撑

位置：`sections/experiments.tex:32`。

相同 encoder forward 次数不推出相同训练时间。G=64 对应 4,096 个相关 reward cells，并有采样、排序、SVD 和 pairwise projection 成本。当前论文没有 RELER versus InfoNCE 的 wall-clock / GPU-hours / memory 对照。

梯度探针中的 CMP versus RLOO 前后向耗时只能比较这两个估计器，不能替代与 InfoNCE 的训练成本比较，也不包含 RAG generator 的端到端成本。

建议补已有日志的端到端耗时和显存表；若没有可靠数据，将句子改成可证明的实现事实：“rollouts do not require additional encoder forward passes”。

## 7. [P2] Product / policy-role 消融存在已知混杂

位置：`sections/experiments.tex:101`、`sections/additional_results.tex:25`。

附录明确声明 paired 和 one-sided paths 与 product path 的 reward equivalence 尚未验证。这比单纯的等步数而非等算力问题更严重：数值差异可能包含候选、mask、标签或 reward normalization 路径的影响。

建议优先核对同一确定性候选和分数输入上的 reward、mask、normalization 是否等价；如果实现不同，再决定是否需要重跑。完成之前应把这几行描述为 recipe variants，不能与严格单因素 CMP 消融一起支撑“每个组件贡献均已验证”。

## 8. [P2] 领域退化应进入主结果解释，而非只写平均收益

位置：Table 1、`sections/experiments.tex:75`。

按当前逐领域导出复算，Q3E-0.6B original 的 RELER 对 InfoNCE 在 12 个领域中胜出 6 个；StackExchange 均值约 +1.93，但 theorem 类约 -1.63。BGE-M3 original 的 coding 类均值约 -3.49。4B GPT reasoning 的 theorem 类约 -1.84。

这些不否定宏平均收益，但说明方法表现包含领域之间的取舍。“reasoning-intensive retrieval”覆盖 theorem/coding，审稿人很可能追问这些退化。

建议正文增加一句明确的 domain trade-off，给出代表值，避免读者把跨 backbone 的 Avg. 提升理解成跨领域一致提升。已有数据足够，不必新增图。

## 另两项值得加强的论证

- **新颖性定位。** 正文相关工作主要区分文本动作与离散文档动作，但 vMF 连续 embedding exploration 的最近工作只在附录一笔带过。[Bendada et al., ICML 2025](https://arxiv.org/abs/2507.00518) 已使用 vMF 采样 embedding 后检索近邻；[Wang et al., SIGIR 2019](https://arxiv.org/abs/1906.03766) 已用 document-space projection 去除无关探索分量。稿件已引用它们，不是漏引问题。建议将差异前移到正文：联合 query/document trainable policy、product-cell/LOO-aware CMP、pair-specific projection 和 shared encoder 的梯度更新，哪些属于本文贡献应更明确。
- **RAG 的贡献强度。** 稿件已经诚实说明单 seed 和 +0.08 F1 的局限，应保留。相对 pretrained encoder，mixed reward 的七数据集 F1 为 +0.27，OOD 仅 +0.02；相对 graded nDCG 的 +0.08 去掉 125-query 的 Bamboogle 后变为 -0.12。因此段标题 “Answer feedback complements ranking feedback” 最好改成试探性表述；如果要强化这一结论，优先补 paired per-query 不确定性分析或独立重复，而非只比较均值。
